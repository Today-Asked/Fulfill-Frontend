# 版面解鎖 — 第一步

把這包解開後蓋到 `Fulfill-Frontend` 專案根目錄。**建議先開一個 branch**：

```bash
git checkout -b responsive-layout
# 解壓縮覆蓋檔案
npm run dev
```

## 沒有動到的

**所有 Supabase 相關邏輯一行都沒改。** 包含：

- `Root.tsx` 裡的登入守衛、onboarding 導向、密碼重設流程 — 完全照抄
- `AuthContext`、`supabase.ts`、`chat.ts`、`useUpload.ts`
- 所有 `src/app/pages/` 底下的頁面
- 資料庫 schema 與 RLS

所以這一步**不可能弄壞既有功能**。壞掉只會壞在版面上，不會壞在資料。

## 為什麼原本桌機看起來是手機

原本的 `Frame` 寫死了：

```tsx
sm:h-[844px] sm:w-[390px] sm:rounded-[40px]
```

不管螢幕多大，內容都被塞進一個 390px 寬、844px 高、圓角 40px 的盒子裡，等於在網頁上放一支模擬手機。現在改成：

- **手機**：滿版，底部浮動導覽列，跟原本觀感一致
- **平板以上**：內容展開，最寬 1440px
- **桌機（lg）**：出現頂部導覽列，底部導覽列隱藏
- **登入／註冊／onboarding**：任何寬度都維持單欄 420px，表單不會被拉爛

原本的漸層光暈保留了，但改成貼著視窗而不是貼著手機外框。

## 檢查清單

跑起來之後確認這幾點：

- [ ] 桌機瀏覽器打開，內容是否滿版而不是中央一支手機
- [ ] 視窗拉窄到手機寬度，底部導覽列是否出現
- [ ] 視窗拉寬，底部導覽列是否消失、頂部導覽列是否出現
- [ ] 登入頁在桌機是否維持窄欄置中
- [ ] 未讀訊息的粉紅小點是否還會亮

## 下一步要決定的事

**頁面內容本身還是手機版排版。** 首頁的作品瀑布流、個人頁、聊天室在桌機上會變成很寬的單欄，讀起來不舒服。這些要一頁一頁調，我會照你們現有的寫法改，不會整個重寫。

另外有個設計方向要你決定：

- 你們現在的視覺是**粉紫霓虹**（fuchsia 光暈 + `#f9a8d4` 粉紅重點色）
- 你 Figma 上那份新設計是**純黑白**

兩種都好看，但要選一個。我這一步刻意保留你們原本的顏色，因為版面和配色同時改，出問題會很難判斷是哪邊造成的。
